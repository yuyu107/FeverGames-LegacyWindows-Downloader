## 五点前端识别

目标包括 GateA、GateB、NetLabel、NetMinor 和 Getter。精确配置校验原始/已修补字节，指定完整哈希的配置还会核对文件哈希。

未知布局的 Auto Profile v2 使用受限的对象字段偏移、调用目标、两个条件跳转、唯一候选、可执行节、邻近 Windows 7/8.1 字符串引用寻找五处位置。补丁必须等长且互不重叠。扫描后及生成临时文件时再次核对原始前端哈希，任何不确定条件都会停止修改。

这不是对任意未来客户端的兼容承诺。新布局测试通过后，可再加入精确配置。

## Go 兼容修改与识别

已验证的 Go 1.23.8 样本存在两条随机数 API 加载路径：运行时初始化与 internal/syscall/windows 的 ProcessPrng 路径。补丁将这两处改为使用 Win7 可用的 advapi32.dll!SystemFunction036，并核对相关指令、字符串及补丁区域。

A/B/C 样本通过完整哈希识别。其他签名变体采用程序主体哈希识别：将 PE CheckSum 和证书目录字段归零，并排除位于文件末尾的证书数据后，对剩余内容计算 SHA-256。该值必须等于已知原版主体哈希；生成后也必须匹配已知修补主体哈希，随后记录生成文件的完整哈希。

此路径只容纳签名及校验和差异，没有实现重新编译后的 Go 函数自动定位。未知主体不会套用旧地址。

## 写入与恢复

先验证配置和源文件，再判断是否已经安装。需要实际写入时检查目标目录及文件的可写条件；不足时以特定退出码交回 CMD，请求系统提权后重试。系统占用也可能表现为写入失败。

两个临时 EXE 及原版备份通过校验后才替换目标。安装失败会尝试恢复两个原版；回滚失败时保留备份并报告错误。备份位于版本目录的 `.FGWin7_150_Backup`，状态文件记录原版和修补后的完整哈希。恢复会拒绝覆盖安装后已发生未知变化的文件。

只读状态检查与可否安装分开：可以识别已修补字节，不代表缺少原版备份时允许重新生成文件。

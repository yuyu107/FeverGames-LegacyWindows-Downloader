# v1.3.3 - Windows 7 安装兼容修复整合版

v1.3.3 是当前建议使用的正式版本。

由于 v1.3.2 Release 已删除，本版本同时包含：

1. **v1.3.2 的 PowerShell 2.0 / 旧 CLR 托管 EXE 验证修复**；
2. **v1.3.3 的 Release CMD 编码 / 换行修复**。

本版本不修改已经完成端到端验证的下载核心，不修改 5 点前端补丁逻辑，也不引入新的并发 / 流水线 / DLL Zstd 实验代码。下载核心、layout A/B、自定义路径、7-Zip 检测、UAC 等待和回滚流程均继续沿用已验证逻辑。

## 一、合入 v1.3.2 修复：Windows 7 / PowerShell 2.0 下 .NET 下载器验证误判

部分较原生的 Windows 7 环境中，旧版安装器可以正常完成前面的步骤：找到 FeverGames、识别已知布局、完成 5 个前端目标位置的精确字节修补，并通过 .NET 4 `csc.exe` 生成新的 `downloadIPC.exe`，但随后会报：

```text
Compiled downloader did not validate as a managed .NET executable.
Installation did not complete successfully. Exit code: 1
```

根因是旧版安装器使用：

```powershell
[Reflection.AssemblyName]::GetAssemblyName($Path)
```

判断生成的 EXE 是否为托管 .NET 程序。在部分 Windows 7 / PowerShell 2.0 环境中，当前 PowerShell 运行于旧 CLR，而脚本可能选择 .NET Framework 4.0 的 `csc.exe` 编译下载器。编译器已经成功生成文件，但旧 CLR 不一定能通过上述方式加载 / 识别目标程序集，于是脚本把“当前 CLR 无法加载”误判成“不是有效的 managed .NET EXE”。

当前版本已改为直接读取 PE Optional Header，并检查 CLR / COM Descriptor 数据目录。安装脚本和状态检查脚本使用同一套 CLR-independent 判断，避免安装成功后再次误报；如果 PE 中不存在有效 CLR Descriptor，仍会在正式覆盖前安全停止。

## 二、v1.3.3 新增修复：Release CMD 编码 / 换行导致 Windows 7 无法运行

v1.3.2 Release ZIP 中的 `.cmd` 入口文件在部分 Windows 7 `cmd.exe` 下会被错误解析，表现为：

```text
锘緻echo off
powershell.exe -> hell.exe
echo -> ho
goto -> to
setlocal -> al
```

v1.3.3 已修复 Release ZIP 的入口文件格式：

- 所有入口 `.cmd` 统一改为 **无 BOM + CRLF**；
- `.cmd` 命令内容保持纯 ASCII，避免中文编码影响命令解释；
- 保留中文文件名，例如 `01_一键安装.cmd`；
- 除入口 CMD 打包格式外，其余安装逻辑保持不变。

## 四、使用方法

完全退出 FeverGames 后运行：

```text
01_一键安装.cmd
```

安装结束后会自动运行状态检查。正常结果应包含：

```text
Frontend patch count: 5/5
downloadIPC.exe = managed Win7 replacement
rollback backup = COMPLETE
RESULT=READY_FOR_WIN7_FEVERGAMES_DOWNLOAD
```

如果遇到问题，请运行：

```text
04_收集诊断.cmd
```
